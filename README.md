# Мониторинг нагрузки и самочувствия преподавателей

Веб-приложение для учёта плановой и фактической нагрузки преподавателей, проведения опросов о самочувствии и анализа связи между рабочим временем и эмоциональным состоянием.

Проект помогает преподавателям вести ежедневный учёт выполненной работы, а руководителям — анализировать распределение нагрузки в пределах назначенных школ и групп школ. Эмоциональные показатели используются только как аналитические данные: система не ставит диагнозы и не должна служить автоматическим основанием для кадровых решений.

## Решаемые задачи

- импорт нормативов и плановой нагрузки из XLSX;
- проверка структуры и содержимого импортируемых файлов;
- хранение версий планов и истории импортов;
- самостоятельный ввод преподавателем фактически затраченного времени;
- учёт внеплановых работ и места их выполнения;
- сопоставление плана, факта и показателей самочувствия;
- проведение версионируемых ежедневных, еженедельных и ежемесячных опросов;
- формирование аналитики по преподавателям, школам и группам школ;
- экспорт отчётов и псевдонимизированных наборов данных для ML-анализа;
- аудит изменений, обращений к чувствительным данным и выгрузок.

## Роли и доступ

Доступ определяется ролью пользователя и его организационной областью.

| Роль | Доступные данные и действия |
|---|---|
| Преподаватель | Собственный план, ввод факта, собственные опросы и аналитика |
| Директор | Только плановая нагрузка закреплённой школы, импорт и экспорт плана |
| Глава | План, факт и ограниченная аналитика назначенных школ |
| Глава группы | Аналитика назначенных групп школ и входящих в них организаций |
| Системный администратор | Пользователи, роли, связи с организациями и системные справочники |

Директор не имеет доступа к фактическим часам, опросам и ML/NLP-показателям. Исходные текстовые ответы на вопросы о самочувствии доступны только преподавателю, который их оставил. Руководителям могут предоставляться числовые показатели, агрегаты и NLP-результаты без исходного текста.

Проверки выполняются на backend по схеме RBAC с дополнительным ограничением записей по школе или группе школ. Скрытие элементов интерфейса не заменяет серверную проверку прав.

## Основные разделы приложения

| Страница | Назначение | Доступ |
|---|---|---|
| `/dashboard` | Дашборд исключительно плановой нагрузки | Директор, глава, глава группы |
| `/workload/plans` | Проверка и импорт XLSX, просмотр и экспорт планов | Директор, глава, глава группы |
| `/my/workload` | Ежедневный ввод фактически выполненных работ | Преподаватель |
| `/my/surveys/daily` | Опрос о нагрузке и самочувствии | Преподаватель |
| `/analytics/teachers/:teacherId` | Сопоставление плана, факта и эмоциональных показателей | Преподаватель — только свои данные; глава и глава группы — назначенная область |
| `/schools` | Школы, преподаватели и действующие нормы | Директор, глава, глава группы |
| `/settings/work-types` | Справочник видов педагогической работы | Просмотр по роли; изменение уполномоченными ролями |
| `/reports` | Формирование разрешённых отчётов и выгрузок | В соответствии с ролью и областью доступа |
| `/settings/users` | Пользователи, роли и назначения доступа | Системный администратор |

## Возможности backend

Backend содержит модели, API-маршруты и сервисы для следующих областей:

- регистрация, вход и Bearer-аутентификация;
- пользователи, роли, школы, группы школ и преподаватели;
- нормы, версии планов, плановые и фактические работы;
- дневная и недельная агрегация нагрузки;
- справочник видов работ с архивированием вместо физического удаления;
- валидация и импорт XLSX-файлов;
- аналитика плановой нагрузки;
- шаблоны опросов, согласия, ответы и история исправлений;
- выгрузки нагрузки, опросов и псевдонимизированных ML-данных;
- NLP-обработка текстовых ответов;
- аудит чувствительных операций.

Основные маршруты нагрузки и опросов имеют префикс `/api/v1`. Регистрация и авторизация находятся под префиксом `/users`. Интерактивная документация FastAPI доступна по адресу `/docs`.

## Быстрый запуск через Docker Compose

Требуются Docker и Docker Compose.

```bash
cd app
mkdir -p data/db data/cache
docker compose up --build
```

После запуска доступны:

- frontend: <http://localhost:8080>;
- backend: <http://localhost:8000>;
- Swagger UI: <http://localhost:8000/docs>;
- проверка состояния: <http://localhost:8000/health>.

Остановка контейнеров:

```bash
docker compose down
```

Docker Compose подключает каталоги `data/db` и `data/cache` как локальные тома. Текущая конфигурация SQLite использует путь `db_store/mood_sync.db`; чтобы хранить базу в подключённом томе, необходимо задать для backend значение `DATABASE_URL=sqlite:////app/db/teacher_workload.db`.

## Локальный запуск backend

Команды выполняются из каталога `app/backend`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload
```

По умолчанию используется SQLite-файл `db_store/mood_sync.db`. Для PostgreSQL перед запуском необходимо указать строку подключения:

```bash
export DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/teacher_workload'
```

При старте приложение идемпотентно добавляет системные роли, базовый справочник видов работ, тестовую административную учётную запись и опубликованные шаблоны опросов.

## Тестирование

Из каталога `app/backend`:

```bash
pytest
```

Запуск с отчётом о покрытии:

```bash
pytest --cov=app --cov-report=term-missing
```

Тесты проверяют авторизацию, модели предметной области, схемы API, сервисы нагрузки и опросов, ролевые ограничения и расширения профиля преподавателя.
