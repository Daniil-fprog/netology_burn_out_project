# Модели данных проекта

## 1. Общее устройство данных

Данные проекта разделены на несколько связанных бизнес-областей:

1. **Пользователи и роли** — учётные записи, системные роли и организационная область доступа.
2. **Организационная структура** — школы, группы школ и педагоги.
3. **Личный дневник** — пользовательские записи, результаты анализа настроения и рекомендации.
4. **Рабочая нагрузка педагогов** — справочник видов работ, нормы, версии планов и фактически выполненные работы.
5. **Опросы о самочувствии** — версии анкет, вопросы, согласия, ответы, история изменений и NLP-анализ.
6. **Служебные процессы** — импорт, экспорт и аудит действий.

Основной организационной границей данных является школа. Пользователь получает доступ к школе отдельно от роли: роль определяет доступные действия, а связь со школой — область видимых данных. Профиль педагога может быть связан с учётной записью пользователя.

Нагрузка хранится в нормализованном виде. Плановая и фактическая работа разбивается на отдельные элементы, каждый из которых связан с педагогом и типом работы. Продолжительность хранится в обычных часах. План имеет версии, а факт группируется в дневные журналы.

Опросы также версионируются. Ответ всегда связан с конкретной версией шаблона, педагогом, школой и периодом оценки. Изменения отправленных ответов и результаты NLP хранятся отдельно.

Большинство доменных моделей используют строковый UUID в поле `id`. Модели с `TimestampMixin` автоматически содержат:

- `created_at` — дата и время создания записи;
- `updated_at` — дата и время последнего изменения.

## 2. Пользователи, роли и доступ

### UserModel

Учётная запись пользователя. Используется для входа в систему и связывает человека с ролями, личными записями и, при необходимости, профилем педагога.

- `id` — идентификатор пользователя;
- `name` — отображаемое имя;
- `login` — логин для входа;
- `password_hash` — хеш пароля;
- `phone` — номер телефона;
- `is_active` — признак активной учётной записи;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `notes` — связанные записи личного дневника;
- `roles` — назначенные пользователю роли.

### RoleModel

Справочник системных ролей: преподаватель, директор, руководитель, руководитель группы школ и системный администратор.

- `id` — идентификатор роли;
- `code` — машинный код роли;
- `name` — отображаемое название;
- `description` — пояснение назначения роли;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `users` — назначения этой роли пользователям.

### UserRoleModel

Связь между пользователем и ролью. Один пользователь может иметь несколько ролей.

- `id` — идентификатор назначения;
- `user_id` — пользователь;
- `role_id` — назначенная роль;
- `created_at` — дата назначения;
- `updated_at` — дата изменения назначения;
- `user` — объект пользователя;
- `role` — объект роли.

### UserSchoolAccessModel

Определяет, к данным какой школы имеет доступ пользователь. Конкретные возможности пользователя определяются его ролями.

- `id` — идентификатор связи;
- `user_id` — пользователь;
- `school_id` — доступная пользователю школа;
- `created_at` — дата выдачи доступа;
- `updated_at` — дата последнего изменения.

### UserSchoolGroupAssignmentModel

Назначает пользователю область управления в виде группы школ. Используется прежде всего для руководителей групп.

- `id` — идентификатор назначения;
- `user_id` — назначенный пользователь;
- `school_group_id` — группа школ;
- `created_at` — дата назначения;
- `updated_at` — дата последнего изменения.

## 3. Организационная структура и педагоги

### SchoolModel

Школа — основная область хранения и разграничения данных педагогов, нагрузки, опросов, импортов и экспортов.

- `id` — идентификатор школы;
- `name` — название школы;
- `external_code` — внешний код для интеграций и импорта;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### SchoolGroupModel

Именованное объединение нескольких школ для общего управления и аналитики.

- `id` — идентификатор группы;
- `name` — название группы школ;
- `external_code` — внешний код группы;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `schools` — связи группы со школами.

### SchoolGroupSchoolModel

Связь школы с группой школ.

- `id` — идентификатор связи;
- `group_id` — группа школ;
- `school_id` — школа, входящая в группу;
- `group` — объект группы;
- `school` — объект школы.

### TeacherModel

Профиль педагога внутри конкретной школы. Может быть связан с пользовательской учётной записью для самостоятельного заполнения данных.

- `id` — идентификатор педагога;
- `school_id` — школа педагога;
- `user_id` — связанная учётная запись;
- `external_id` — внешний идентификатор для импорта;
- `full_name` — полное имя;
- `subject` — основной предмет или направление работы;
- `is_active` — признак действующего педагога;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `school` — объект школы;
- `user` — объект связанного пользователя.

## 4. Личный дневник и рекомендации

Этот раздел представляет отдельный пользовательский контур: пользователь сохраняет текстовую запись, система анализирует её настроение и подбирает рекомендации.

### NoteModel

Текстовая запись пользователя и результаты её автоматической обработки.

- `id` — идентификатор записи;
- `user_id` — автор записи;
- `orig_text` — исходный текст;
- `translate_text` — переведённый текст;
- `translate_status` — состояние перевода;
- `sentiment_label` — определённая категория настроения;
- `sentiment_score` — числовая оценка настроения;
- `model_confidence` — уверенность модели анализа;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `user` — объект автора;
- `recommendations` — подобранные рекомендации.

### RecommendationModel

Справочник рекомендаций, которые выдаются пользователю в зависимости от оценки настроения.

- `id` — идентификатор рекомендации;
- `rec_name` — короткое название;
- `rec_text` — текст рекомендации;
- `mood_type` — категория настроения, для которой предназначена рекомендация;
- `score_from` — нижняя граница подходящей оценки;
- `score_to` — верхняя граница подходящей оценки;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `notes` — записи дневника, для которых была выбрана рекомендация.

### NoteRecommendationModel

Связь между записью дневника и выданной рекомендацией.

- `note_id` — запись дневника;
- `recommendation_id` — рекомендация.

## 5. Рабочая нагрузка педагогов

Нагрузка разделена на план и факт. Каждый элемент связан со справочником типов работ. Благодаря этому новые виды работ добавляются в справочник без добавления отдельных колонок в таблицы нагрузки.

### WorkTypeModel

Справочник типов педагогической работы: уроки, подготовка, проверка работ, документация и другие категории.

- `id` — идентификатор типа работы;
- `code` — стабильный машинный код;
- `name` — отображаемое название;
- `category_group` — более крупная группа работ;
- `complexity_weight` — коэффициент сложности работы;
- `requires_comment` — требуется ли пояснение при заполнении;
- `is_active` — доступен ли тип для новых записей;
- `description` — описание типа работы;
- `archived_at` — дата архивирования;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### TeacherWorkloadNormModel

Индивидуальная недельная норма педагога, действующая в заданном периоде.

- `id` — идентификатор нормы;
- `teacher_id` — педагог;
- `effective_from` — начало действия нормы;
- `effective_to` — окончание действия нормы;
- `contract_teaching_hours_per_week` — договорная недельная нагрузка;
- `standard_teaching_hours_per_rate` — норматив часов на одну ставку;
- `comment` — пояснение к норме;
- `plan_source` — источник сведений о норме;
- `source_import_id` — импорт, из которого получена норма;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### WorkloadPlanVersionModel

Заголовок версии плана нагрузки школы. Позволяет публиковать новые планы, сохраняя историю предыдущих версий.

- `id` — идентификатор версии;
- `school_id` — школа, для которой создан план;
- `version` — номер версии;
- `status` — состояние версии;
- `effective_from` — начало периода плана;
- `effective_to` — окончание периода плана;
- `source_import_id` — импорт, создавший версию;
- `created_by` — пользователь, создавший план;
- `published_at` — дата публикации;
- `change_comment` — описание изменений;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `items` — элементы этой версии плана.

### PlannedWorkItemModel

Отдельная запланированная работа конкретного педагога на определённую дату.

- `id` — идентификатор элемента;
- `plan_version_id` — версия плана;
- `teacher_id` — педагог;
- `work_type_id` — тип работы;
- `work_date` — дата выполнения;
- `day_type` — тип дня, например учебный или выходной;
- `subject` — предмет, связанный с работой;
- `duration_hours` — запланированная продолжительность в обычных часах;
- `sequence_no` — порядковый номер однотипной работы в рамках дня;
- `comment` — пояснение;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `plan_version` — объект версии плана;
- `work_type` — объект типа работы.

### DailyWorkLogModel

Дневной журнал фактической работы педагога. Объединяет все выполненные за день работы и хранит состояние заполнения дня.

- `id` — идентификатор журнала;
- `teacher_id` — педагог;
- `work_date` — дата журнала;
- `day_type` — тип дня;
- `status` — состояние заполнения;
- `comment` — общий комментарий за день;
- `completed_at` — дата завершения заполнения;
- `completed_by` — пользователь, завершивший журнал;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `entries` — фактические работы за день.

### ActualWorkEntryModel

Отдельная фактически выполненная работа внутри дневного журнала.

- `id` — идентификатор записи;
- `daily_log_id` — дневной журнал;
- `planned_work_item_id` — связанный элемент плана, если работа была запланирована;
- `work_type_id` — тип работы;
- `duration_hours` — фактическая продолжительность в обычных часах;
- `location` — место выполнения: школа, дом или другое место;
- `comment` — комментарий к конкретной работе;
- `created_by` — пользователь, создавший запись;
- `updated_by` — пользователь, изменивший запись;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `daily_log` — объект дневного журнала;
- `planned_work_item` — связанная плановая работа;
- `work_type` — объект типа работы.

## 6. Опросы и оценка самочувствия

Каталог опросов отделён от ответов. Шаблон и вопросы описывают конкретную версию анкеты, а ответы педагога всегда ссылаются на эту версию. Согласия, история исправлений и NLP-обработка хранятся отдельно.

### SurveyTemplateModel

Версия шаблона ежедневного, еженедельного или ежемесячного опроса.

- `id` — идентификатор версии шаблона;
- `code` — стабильный код опроса;
- `version` — номер или обозначение версии;
- `title` — название опроса;
- `cadence` — периодичность заполнения;
- `locale` — язык и регион шаблона;
- `definition_jsonb` — полное исходное описание формы;
- `content_hash` — контрольный хеш содержимого;
- `status` — состояние шаблона;
- `is_current` — является ли версия текущей;
- `published_at` — дата публикации;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### SurveyQuestionModel

Вопрос внутри определённой версии шаблона.

- `id` — идентификатор вопроса;
- `template_id` — версия шаблона;
- `code` — стабильный код вопроса;
- `title` — текст вопроса;
- `type` — тип ожидаемого ответа;
- `position` — порядок отображения;
- `required` — является ли ответ обязательным;
- `settings_jsonb` — настройки шкалы, вариантов ответа и другой логики;
- `created_at` — дата создания.

### SurveyConsentModel

Отзывное согласие педагога на конкретную цель обработки данных опросов.

- `id` — идентификатор согласия;
- `school_id` — школа;
- `teacher_id` — педагог;
- `policy_version` — версия политики обработки;
- `purpose` — цель обработки;
- `granted_at` — дата предоставления согласия;
- `withdrawn_at` — дата отзыва;
- `method` — способ получения согласия;
- `proof_reference` — ссылка или описание подтверждения;
- `created_at` — дата создания записи.

### SurveyResponseModel

Ответ педагога на конкретную версию опроса за определённый период.

- `id` — идентификатор ответа;
- `school_id` — школа;
- `teacher_id` — педагог;
- `template_id` — версия шаблона;
- `cadence` — периодичность опроса;
- `assessment_date` — дата оценки состояния;
- `period_start` — начало оцениваемого периода;
- `period_end` — окончание оцениваемого периода;
- `comment_reference_date` — дата, к которой относится текстовый комментарий;
- `status` — состояние ответа;
- `source` — источник заполнения;
- `consent_record_id` — согласие, на основании которого сохранён ответ;
- `submitted_at` — дата отправки;
- `client_request_id` — идентификатор клиентского запроса для защиты от повторной отправки;
- `lock_version` — версия записи для контроля конкурентного изменения;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `template` — объект шаблона;
- `answers` — ответы на отдельные вопросы.

### SurveyAnswerModel

Ответ на один вопрос анкеты.

- `id` — идентификатор ответа;
- `response_id` — общий ответ на опрос;
- `question_id` — вопрос;
- `value_jsonb` — значение ответа в формате, соответствующем типу вопроса;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения;
- `question` — объект вопроса.

### SurveyResponseRevisionModel

Неизменяемый снимок предыдущего состояния отправленного ответа. Используется для истории исправлений и аудита.

- `id` — идентификатор ревизии;
- `response_id` — изменённый ответ;
- `revision_no` — порядковый номер ревизии;
- `actor_id` — пользователь, выполнивший изменение;
- `reason` — причина изменения;
- `previous_answers_jsonb` — предыдущий набор ответов;
- `changed_at` — дата изменения;
- `change_type` — вид изменения.

### SurveyNLPAnalysisModel

Задание на NLP-обработку текстового ответа и результат анализа.

- `id` — идентификатор анализа;
- `response_id` — ответ на опрос;
- `answer_id` — конкретный текстовый ответ;
- `status` — состояние обработки;
- `model_name` — название использованной модели;
- `model_version` — версия модели;
- `preprocessing_version` — версия подготовки текста;
- `schema_version` — версия структуры результата;
- `result_jsonb` — результат анализа;
- `error_code` — код ошибки обработки;
- `attempt_count` — количество попыток;
- `stale` — признак устаревшего результата после изменения ответа;
- `analyzed_at` — дата завершения анализа;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

## 7. Импорт, экспорт и аудит

Эти модели не являются основными бизнес-сущностями, но обеспечивают воспроизводимость загрузок, формирование файлов и контроль действий пользователей.

### ImportBatchModel

Одна операция импорта файла нагрузки и итог её обработки.

- `id` — идентификатор импорта;
- `school_id` — школа, в которую загружены данные;
- `original_filename` — исходное имя файла;
- `stored_file_key` — ключ или путь сохранённого файла;
- `sha256` — контрольный хеш файла;
- `template_version` — версия формата импортируемого шаблона;
- `status` — состояние импорта;
- `mode` — режим обработки данных;
- `effective_from` — дата начала действия импортируемых данных;
- `rows_total` — количество обработанных строк;
- `rows_created` — количество созданных записей;
- `rows_updated` — количество обновлённых записей;
- `rows_skipped` — количество пропущенных записей;
- `validation_report` — структурированный отчёт проверки;
- `uploaded_by` — пользователь, загрузивший файл;
- `imported_at` — дата завершения импорта;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### ExportJobModel

Задание на формирование отчёта или исследовательской выгрузки.

- `id` — идентификатор задания;
- `requested_by` — пользователь, запросивший экспорт;
- `school_id` — школа выгрузки;
- `school_group_id` — группа школ выгрузки;
- `report_type` — вид отчёта;
- `format` — формат файла;
- `filters_jsonb` — параметры отбора данных;
- `status` — состояние формирования;
- `row_count` — количество строк результата;
- `stored_file_key` — ключ или путь готового файла;
- `expires_at` — срок доступности файла;
- `downloaded_at` — дата последнего скачивания;
- `download_count` — количество скачиваний;
- `error_message` — описание ошибки;
- `created_at` — дата создания;
- `updated_at` — дата последнего изменения.

### AuditEventModel

Неизменяемая запись о значимом действии: изменении данных, импорте, экспорте или обращении к защищённой операции.

- `id` — идентификатор события;
- `actor_id` — пользователь, выполнивший действие;
- `action` — вид действия;
- `entity_type` — вид затронутой сущности;
- `entity_id` — идентификатор затронутой записи;
- `school_id` — школа, в контексте которой произошло действие;
- `import_batch_id` — связанная операция импорта;
- `purpose` — заявленная цель операции;
- `changed_at` — дата и время события;
- `changes` — структурированное описание изменений.

## 8. Ключевые связи между разделами

- Пользователь получает системные возможности через `UserRoleModel`.
- Область данных пользователя задают `UserSchoolAccessModel` и `UserSchoolGroupAssignmentModel`.
- `TeacherModel` связывает школьного педагога с учётной записью пользователя.
- Норма, план и факт нагрузки связываются с педагогом через `teacher_id`.
- Плановая и фактическая работа используют общий справочник `WorkTypeModel`.
- Фактическая работа может ссылаться на соответствующий элемент плана.
- Ответ на опрос связывает школу, педагога и версию шаблона.
- Согласия, ревизии и NLP-результаты позволяют отдельно контролировать обработку чувствительных данных.
- `ImportBatchModel`, `ExportJobModel` и `AuditEventModel` обеспечивают трассируемость служебных операций.
