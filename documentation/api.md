# API проекта

## 1. Общее устройство API

API разделён на четыре области:

1. **Системные эндпоинты** — проверка работы приложения.
2. **Авторизация и пользователи** — регистрация, вход и получение учётных записей.
3. **Рабочая нагрузка** — школы, педагоги, справочник работ, импорт, плановая и фактическая нагрузка.
4. **Опросы** — каталог анкет, согласия, ответы, аналитика, экспорт и NLP-обработка.

Эндпоинты нагрузки и опросов имеют общий префикс `/api/v1`. Эндпоинты пользователей используют префикс `/users`. За исключением регистрации, входа и системных проверок, обработчики требуют Bearer-токен. Доступ к данным дополнительно ограничивается ролью пользователя и школой.

Общие проверки авторизации находятся в [security.py](../backend/app/core/security.py), а проверки ролей и области доступа — в [access.py](../backend/app/core/access.py). Это вспомогательные модули ядра, а не бизнес-сервисы.

В описании ниже «отдельный сервис не используется» означает, что обработчик работает с моделями и базой данных непосредственно в роутере.

## 2. Системные эндпоинты

### `GET /home`

Проверяет, что FastAPI-приложение запущено и отвечает на запросы.

- **Результат:** объект с сообщением `FastAPI работает`.
- **Сервис:** отдельный сервис не используется.

### `GET /health`

Используется для технической проверки состояния приложения.

- **Результат:** объект со значением `status: ok`.
- **Сервис:** отдельный сервис не используется.

## 3. Авторизация и пользователи

### `POST /users/register`

Создаёт новую учётную запись пользователя.

- **Входные данные:** имя, логин, пароль и необязательный телефон.
- **Результат:** созданный пользователь без хеша пароля.
- **Сервис:** [user_service.py](../backend/app/services/user_service.py).

### `POST /users/login`

Проверяет логин и пароль и создаёт токен авторизации.

- **Входные данные:** логин и пароль.
- **Результат:** access-токен и тип токена `bearer`.
- **Сервис:** [user_service.py](../backend/app/services/user_service.py).

### `GET /users/me`

Возвращает учётную запись текущего авторизованного пользователя.

- **Результат:** идентификатор, имя, логин, телефон, активность и даты создания и изменения пользователя.
- **Сервис:** отдельный сервис не используется.

### `GET /users/`

Возвращает список всех учётных записей пользователей.

- **Результат:** массив пользователей без хешей паролей.
- **Сервис:** отдельный сервис не используется.

### `GET /users/{userId}`

Ищет пользователя по идентификатору.

- **Параметры:** `userId` — идентификатор пользователя.
- **Результат:** массив с найденным пользователем или пустой массив.
- **Сервис:** отдельный сервис не используется.

## 4. Сводная аналитика плановой нагрузки

### `GET /api/v1/dashboard/planned`

Формирует сводный экран плановой нагрузки школы за период.

- **Параметры:** `school_id`, `date_from`, `date_to`.
- **Результат:** KPI по часам и педагогам, недельная динамика, распределение по предметам и школам, а также строки по педагогам с отклонением от нормы.
- **Сервис:** [analytics_service.py](../backend/app/services/analytics_service.py).

## 5. Справочник типов работ

### `GET /api/v1/work-types`

Возвращает доступные типы педагогических работ.

- **Параметры:** `include_archived` — включить архивные типы работ.
- **Результат:** массив типов работ с кодом, названием, группой, коэффициентом сложности, состоянием и описанием.
- **Сервис:** [work_type_service.py](../backend/app/services/work_type_service.py).

### `POST /api/v1/work-types`

Добавляет новый тип работы в общий справочник.

- **Входные данные:** код, название, группа, коэффициент сложности, требование комментария и описание.
- **Результат:** созданный тип работы.
- **Сервис:** [work_type_service.py](../backend/app/services/work_type_service.py).

### `PATCH /api/v1/work-types/{work_type_id}`

Изменяет свойства существующего типа работы.

- **Параметры:** `work_type_id` — идентификатор типа работы.
- **Входные данные:** изменяемые поля типа работы.
- **Результат:** обновлённый тип работы.
- **Сервис:** [work_type_service.py](../backend/app/services/work_type_service.py).

### `POST /api/v1/work-types/{work_type_id}/archive`

Архивирует тип работы, чтобы его нельзя было выбирать для новых записей, сохраняя исторические данные.

- **Параметры:** `work_type_id` — идентификатор типа работы.
- **Результат:** архивированный тип работы с обновлённым состоянием.
- **Сервис:** [work_type_service.py](../backend/app/services/work_type_service.py).

## 6. Школы, педагоги и доступ

### `POST /api/v1/schools`

Создаёт школу, выдаёт создавшему пользователю доступ к ней и назначает роль директора.

- **Входные данные:** название школы и необязательный внешний код.
- **Результат:** идентификатор, название и внешний код созданной школы.
- **Сервис:** отдельный сервис не используется.

### `POST /api/v1/schools/{school_id}/teachers`

Создаёт профиль педагога в школе. При необходимости связывает его с учётной записью пользователя.

- **Параметры:** `school_id` — школа педагога.
- **Входные данные:** внешний идентификатор, предмет, полное имя и необязательный `user_id`.
- **Результат:** идентификатор педагога, внешний идентификатор, предмет и признак активности.
- **Сервис:** отдельный сервис не используется.

### `POST /api/v1/schools/{school_id}/access`

Выдаёт пользователю доступ к школе и назначает указанную роль.

- **Параметры:** `school_id` — школа, к которой выдаётся доступ.
- **Входные данные:** идентификатор пользователя и роль.
- **Результат:** созданное назначение доступа с пользователем, школой и ролью.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/teachers`

Возвращает педагогов школы и их действующие нормы нагрузки. Для учётной записи только с ролью преподавателя результат ограничивается собственным профилем.

- **Параметры:** необязательный предмет, номер и размер страницы.
- **Результат:** постраничный список педагогов с внешним идентификатором, предметом, активностью и текущей нормой.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/teachers/{teacher_id}/norms`

Возвращает историю норм нагрузки выбранного педагога.

- **Параметры:** школа и педагог.
- **Результат:** массив норм с периодами действия, договорными и нормативными часами, долей ставки, комментарием и источником плана.
- **Сервис:** отдельный сервис не используется.

## 7. Импорт нагрузки

### `POST /api/v1/schools/{school_id}/workload/imports/validate`

Проверяет XLSX-файл нагрузки без записи импортируемых бизнес-данных.

- **Входные данные:** XLSX-файл, дата начала действия и режим `insert_only` или `upsert`.
- **Результат:** отчёт валидации файла с обнаруженными ошибками и сведениями о данных импорта.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `POST /api/v1/schools/{school_id}/workload/imports`

Загружает XLSX-файл и импортирует нормы и плановую нагрузку школы. Фактическую нагрузку преподаватели вводят самостоятельно, поэтому лист ежедневного учёта при импорте не загружается.

- **Входные данные:** XLSX-файл, дата начала действия, режим импорта и необязательный заголовок `Idempotency-Key`.
- **Результат:** карточка операции импорта со статусом, контрольной суммой, счётчиками строк и отчётом валидации.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `GET /api/v1/schools/{school_id}/workload/imports`

Возвращает историю импортов нагрузки для школы.

- **Параметры:** номер и размер страницы.
- **Результат:** постраничный список операций импорта и результатов их обработки.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/workload/imports/{import_id}`

Возвращает сведения об одной операции импорта.

- **Параметры:** идентификаторы школы и импорта.
- **Результат:** карточка импорта со статусом, режимом, счётчиками и отчётом проверки.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/workload/imports/{import_id}/file`

Скачивает исходный XLSX-файл выбранного импорта.

- **Параметры:** идентификаторы школы и импорта.
- **Результат:** XLSX-файл с исходным именем загруженного документа.
- **Сервис:** отдельный сервис не используется.

## 8. Плановая и фактическая нагрузка

### `GET /api/v1/schools/{school_id}/workload/daily`

Возвращает плановую и фактическую нагрузку по дням. Преподаватель видит только свои данные.

- **Параметры:** необязательные педагог, начало и конец периода, сортировка, номер и размер страницы.
- **Результат:** постраничные дневные записи с педагогом, планом, фактом и рассчитанными метриками.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `GET /api/v1/schools/{school_id}/workload/weekly`

Агрегирует дневную нагрузку педагогов по неделям.

- **Параметры:** необязательные педагог, границы периода, номер и размер страницы.
- **Результат:** недельные плановые и фактические часы, отклонение, отношение факта к плану, выходные часы и признаки отсутствующих данных.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `PATCH /api/v1/schools/{school_id}/workload/daily/{record_id}`

Позволяет преподавателю изменить собственный дневной журнал и перечень фактически выполненных работ.

- **Параметры:** школа, дневная запись и необязательный заголовок `If-Match` для защиты от одновременного изменения.
- **Входные данные:** тип дня, состояние журнала, комментарий и полный список фактических работ.
- **Результат:** обновлённая дневная запись с планом, фактом и метриками.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `GET /api/v1/schools/{school_id}/workload/exports`

Формирует XLSX-выгрузку нагрузки школы или отдельного педагога.

- **Параметры:** период, необязательный педагог и обозначение отчёта.
- **Результат:** XLSX-файл с нормами, планом и доступными пользователю фактическими данными.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

### `GET /api/v1/schools/{school_id}/workload/template`

Формирует пустой шаблон для последующего импорта нагрузки.

- **Результат:** XLSX-файл версии 1.0 с пустыми листами норм, плана и ежедневного учёта.
- **Сервис:** отдельный сервис не используется.

## 9. Каталог опросов

### `GET /api/v1/schools/{school_id}/surveys`

Возвращает опубликованные текущие версии доступных опросов.

- **Результат:** массив опросов с кодом, версией, названием, периодичностью и ожидаемым временем заполнения.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/surveys/{code}`

Возвращает полное описание текущей версии выбранного опроса.

- **Параметры:** код опроса.
- **Результат:** JSON-определение формы с метаданными и вопросами.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/surveys/{code}/versions/{version}`

Возвращает полное описание конкретной опубликованной версии опроса.

- **Параметры:** код и версия опроса.
- **Результат:** JSON-определение выбранной версии формы.
- **Сервис:** отдельный сервис не используется.

### `POST /api/v1/schools/{school_id}/surveys/templates/import`

Проверяет или загружает каталог шаблонов опросов. Эндпоинт доступен только системному администратору.

- **Входные данные:** JSON-файл каталога и параметр `dry_run`.
- **Результат:** при `dry_run=true` — количество найденных шаблонов и вопросов; при `false` — результат загрузки версий шаблонов в БД.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

## 10. Согласия на обработку опросов

### `POST /api/v1/schools/{school_id}/teachers/{teacher_id}/survey-consents`

Сохраняет согласие текущего преподавателя на указанную цель обработки данных.

- **Входные данные:** версия политики, цель обработки, способ получения и необязательное подтверждение.
- **Результат:** идентификатор согласия, педагог, цель и дата предоставления.
- **Сервис:** отдельный сервис не используется.

### `POST /api/v1/schools/{school_id}/survey-consents/{consent_id}/withdraw`

Отзывает ранее выданное согласие текущего преподавателя.

- **Параметры:** идентификатор согласия.
- **Результат:** идентификатор согласия и дата его отзыва.
- **Сервис:** отдельный сервис не используется.

## 11. Заполнение и просмотр опросов

### `POST /api/v1/schools/{school_id}/survey-responses`

Создаёт черновик или сразу отправленный ответ текущего преподавателя на опрос.

- **Входные данные:** код и версия опроса, даты оценки и периода, источник, состояние, согласие, идентификатор клиентского запроса и ответы на вопросы.
- **Результат:** созданный ответ, сохранённые значения вопросов, количество ответов и состояние NLP-задания.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `PATCH /api/v1/schools/{school_id}/survey-responses/{response_id}`

Обновляет ответы в собственном черновике опроса.

- **Параметры:** идентификатор ответа и необязательный заголовок `If-Match` с версией черновика.
- **Входные данные:** изменяемые ответы на вопросы.
- **Результат:** обновлённый черновик с ответами и новой версией блокировки.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `POST /api/v1/schools/{school_id}/survey-responses/{response_id}/submit`

Проверяет заполненность черновика и переводит его в состояние отправленного ответа.

- **Параметры:** идентификатор ответа.
- **Результат:** отправленный ответ с датой отправки; для текстового комментария создаётся ожидающее NLP-задание.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `POST /api/v1/schools/{school_id}/survey-responses/{response_id}/corrections`

Исправляет ранее отправленный ответ, сохраняя снимок предыдущих значений в истории.

- **Входные данные:** причина исправления и обновлённые ответы.
- **Результат:** исправленный ответ; прежние NLP-результаты помечаются устаревшими.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `POST /api/v1/schools/{school_id}/survey-responses/{response_id}/withdraw`

Отзывает отправленный ответ преподавателя и отменяет связанную необработанную NLP-обработку.

- **Параметры:** идентификатор ответа.
- **Результат:** ответ в состоянии `withdrawn` с сохранённой историей предыдущих значений.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `GET /api/v1/schools/{school_id}/survey-responses`

Возвращает ответы на опросы школы с фильтрацией. Для преподавателя выборка ограничивается собственными ответами.

- **Параметры:** педагог, код опроса, состояние, период, номер и размер страницы.
- **Результат:** постраничный список ответов; текстовые комментарии включаются только для владельца ответа.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `GET /api/v1/schools/{school_id}/survey-responses/{response_id}`

Возвращает один ответ на опрос с учётом доступа к выбранному педагогу.

- **Параметры:** идентификатор ответа.
- **Результат:** сведения об опросе, периоде, состоянии и ответах; чувствительные комментарии доступны владельцу.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `GET /api/v1/schools/{school_id}/teachers/{teacher_id}/survey-history`

Возвращает хронологию опросов выбранного педагога.

- **Параметры:** педагог, номер и размер страницы.
- **Результат:** постраничный список ответов от новых к старым с ограничением видимости комментариев.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

## 12. Аналитика и экспорт опросов

### `GET /api/v1/schools/{school_id}/survey-analytics/completion`

Рассчитывает полноту заполнения ежедневных, еженедельных и ежемесячных опросов за период.

- **Параметры:** начало и конец периода, необязательный педагог.
- **Результат:** по каждому педагогу возвращаются псевдоним, количество заполненных и ожидаемых опросов, доля заполнения и разбивка по периодичности.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/surveys/exports`

Выгружает отправленные ответы школы в псевдонимизированном виде.

- **Параметры:** формат `xlsx`, `csv` или `json`, вид отчёта и необязательный период.
- **Результат:** файл выбранного формата с ответами, идентификатором ответа, псевдонимом педагога и сведениями об опросе.
- **Сервис:** [survey_service.py](../backend/app/services/survey_service.py).

### `GET /api/v1/schools/{school_id}/ml/teacher-wellbeing/dataset`

Формирует исследовательский набор признаков, объединяющий самочувствие и нагрузку педагогов.

- **Параметры:** начало и конец периода, версия признаков `v1`.
- **Результат:** CSV-файл с псевдонимами педагогов, скользящими показателями опросов и плановыми и фактическими часами нагрузки.
- **Сервис:** [workload_service.py](../backend/app/services/workload_service.py).

## 13. NLP и объединённая история

### `GET /api/v1/schools/{school_id}/survey-responses/{response_id}/nlp`

Возвращает историю NLP-обработки текстового ответа на опрос.

- **Параметры:** идентификатор ответа.
- **Результат:** массив запусков обработки со статусом, моделью, версией, результатом, признаком устаревания и датой анализа.
- **Сервис:** отдельный сервис не используется.

### `POST /api/v1/schools/{school_id}/survey-responses/{response_id}/nlp/reprocess`

Создаёт повторное задание на NLP-анализ текстового ответа преподавателя при наличии согласия на исследовательскую обработку.

- **Параметры:** идентификатор ответа.
- **Результат:** идентификатор нового задания и состояние `pending`; HTTP-статус `202` означает, что обработка принята, но ещё не завершена.
- **Сервис:** отдельный сервис не используется.

### `GET /api/v1/schools/{school_id}/teachers/{teacher_id}/workload-and-wellbeing`

Объединяет фактическую нагрузку и отправленные опросы педагога в общую временную шкалу.

- **Параметры:** педагог, начало и конец периода.
- **Результат:** упорядоченный по датам массив, где для каждого дня указаны фактические часы и связанные ответы на опросы.
- **Сервисы:** [survey_service.py](../backend/app/services/survey_service.py), [workload_service.py](../backend/app/services/workload_service.py).
